# Conventions

The rules new code in this repository follows. Most are enforced by a test;
the test is named next to each rule. They follow the same standards as
[FloorSync](https://github.com/rileyrushton05/floorsync), where I owned the
database, data APIs and migrations, adapted to a smaller, serverless app.

## API

**Errors are RFC 9457 Problem Details.** Every error response, from domain
errors to unknown routes, validation failures and unexpected crashes, is
`application/problem+json`:

```json
{
  "type": "urn:meal-planner:problem:duplicate-name",
  "title": "Conflict",
  "status": 409,
  "detail": "A meal named 'Spaghetti Bolognese' already exists.",
  "instance": "/api/meals"
}
```

- `detail` is a sentence written for the person using the app; the
  frontend shows it as is. It never contains internals.
- `type` values are part of the contract. Add new ones; never rename one.
- Validation failures add `invalid_params`, one `{name, reason}` per field.
- Domain code raises exceptions from `app.exceptions`; `server/problems.py`
  is the one place that maps them to statuses and types.
- Unexpected exceptions become a generic 500 in `UnexpectedErrorMiddleware`,
  inside the request-context middleware so they keep their request id.

Tests: `tests/test_api_conventions.py` (problem details section).

**Request bodies are strict.** Every request model inherits `RequestSchema`
(`extra="forbid"`), so an unknown or misspelt field is a 422 rather than
silently dropped. Tests: strict requests section.

**The OpenAPI document is the contract.** `docs/openapi.json` is exported
from the app by `scripts/export_openapi.py`, and the frontend's types in
`web/src/api/schema.ts` are generated from it; `web/src/api/types.ts` only
gives them app-facing names. Both files are committed. A test fails if the
document is stale, and CI fails if the generated TypeScript is. Responses
inherit `ResponseSchema`, documented in serialization mode, so every field
the server always sends is required in the generated types; requests inherit
`RequestSchema`, where defaulted fields stay optional. Every error is
documented as `Problem` in `application/problem+json`.
Tests: `tests/test_openapi_contract.py`.

**HTTP semantics.** Creating returns `201 Created` with a `Location` header
that can be fetched. Deleting returns `204` with no body. Asking for a row
that does not exist (or, after accounts, belongs to someone else) is a `404`.

## Observability

- Every response carries `X-Request-ID`, generated by the server. A
  client-supplied value is ignored.
- Every log line written while serving a request carries that id.
- Each request ends with one `http_request_completed` event: method, route
  template (`/api/meals/{meal_id}`, never the concrete path), status code
  and duration.
- Never logged: request or response bodies, query strings, cookies,
  authorization headers, passwords, tokens, database URLs.
- On Vercel logs are JSON lines; locally they are text. Override with
  `MEAL_PLANNER_LOG_FORMAT=json|text`. Run uvicorn with `--no-access-log` so
  requests are not logged twice.

Tests: request correlation and logging sections.

**Health checks.** `/health/live` touches nothing and says the process is up.
`/health/ready` runs `select 1` with a bounded connect timeout and returns a
503 problem when the database is unreachable. The keep-warm workflow pings
`/health/ready`. `/health` remains an alias of `/health/live`.

## Frontend

- Server state lives in TanStack Query, one cache entry per resource: the
  library (meals, ingredient names, templates), one plan per week, one
  grocery list per week. Components never fetch.
- Mutations patch the cache from the API's response instead of refetching.
  When the server's effect is known (deleting a meal unassigns it from every
  week), the cache is corrected in place. A response is filed under the
  resource it names, not whatever is on screen when it arrives.
- Pending state is per area (`mealsPending`, `planPending`,
  `groceryPending`), never one flag that freezes the whole app.
- View state that should survive a refresh or a shared link (tab, week)
  lives in the URL, written with `replaceState` so the back button is not
  filled with every week visited. Unknown values fall back to a default.
- Types come from the generated API contract (see API above).

Tests: `web/src/hooks/usePlanner.test.ts`, `web/src/App.test.tsx`.

## Database

- Schema changes go through Alembic migrations only, reviewed by hand in
  both directions. CI applies every migration to an empty Postgres, runs
  `alembic check`, and downgrades to base.
- One transaction per request, opened in `server/deps.py`.
- Queries are SQLAlchemy constructs, never string-built SQL.
- Reads that need related rows use explicit joins; there are no ORM
  relationships to lazy-load.
- Integer primary keys, and money as integer cents. Recipe quantities are
  floats because measurements are approximate.

Planned with the accounts migration: a constraint naming convention, plural
table names, named check and unique constraints, indexed foreign keys,
`created_at`/`updated_at` on every table, and a test that checks all of it.

## Tests

- The suite runs on SQLite and on Postgres in CI.
- When `TEST_DATABASE_URL` is set, the suite refuses to start unless the
  database name ends in `_test`, because it drops every table in it. The
  Postgres CI leg sets `REQUIRE_TEST_DATABASE=1`, so a missing URL fails
  instead of silently falling back to SQLite.
  Tests: `tests/test_database_safety.py`.
- Coverage floors are enforced in CI: 95% for Python, and per-metric floors
  for the frontend in `web/vitest.config.ts`. Raise them as coverage rises;
  never lower one to make a build pass.
- `pyright` type-checks `app/` and `server/`.
- Playwright runs the production build in Chromium against the real API on
  a fresh SQLite database (`npm run test:e2e`, and a CI job). Each spec works
  in its own week and names its own meals, so specs never depend on each
  other. Locate elements the way a user would (role and accessible name);
  if a control cannot be found that way, fix its accessible name rather than
  reaching for a CSS selector.
  Tests: `web/e2e/planner.spec.ts`.
